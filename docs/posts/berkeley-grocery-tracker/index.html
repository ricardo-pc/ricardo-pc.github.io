Berkeley Grocery Tracker

Software Engineering
A live grocery price tracker across nine Berkeley-area stores, with automated collection, product matching, price history, and basket comparison.

NoteProject Overview

A fully automated grocery price tracker covering nine Berkeley-area stores across Trader Joe’s, Whole Foods, and Safeway. Scrapers run on a monthly schedule, prices land in a Postgres database, and a Next.js dashboard lets you compare items across stores and estimate basket cost. I designed the product, data model, and validation approach; Codex accelerated implementation as part of an OpenAI challenge.

Live site

The Problem

Living in Berkeley, I noticed that grocery prices vary a lot depending on which store you go to and when. A dozen eggs at Trader Joe’s and the same dozen at Whole Foods are rarely the same price, and the gap shifts over time. There was no easy way to see this data in one place, let alone track it over time or figure out which store makes the most sense for your weekly basket. I wanted to build exactly that.

The Experiment: Building with Codex

OpenAI opened a challenge for developers to build with Codex. I used it to test a practical question: how much of a real, multi-layer product could I delegate while still owning the architecture and quality of the result?

The entire stack was designed and built through Codex. I described what I wanted, iterated on the output, reviewed the code, and pushed forward. It was less about avoiding effort and more about compressing weeks of setup into days, without cutting corners on architecture.

What It Does

The live site shows price data for a curated set of staple items, things like eggs, milk, bananas, chicken breast, olive oil, across multiple Berkeley-area locations. You can:

  • See the latest prices for each item across stores
  • Explore price trends over time with a time-series view
  • Build a basket and estimate total cost, both at the cheapest individual store per item and at the single best store overall
  • Compare against Berkeley meal plan pricing as a reference point

How It Works

The data pipeline runs automatically. Three scrapers, one per grocery chain, pull full product catalogs from each store on a monthly schedule using GitHub Actions. Trader Joe’s exposes an internal GraphQL API; Whole Foods has a structured product feed; Safeway required Playwright to handle anti-bot protections on some runs.

Raw scraped data lands in a staging table first. From there, a matching pipeline normalizes product names across stores into canonical items, using fuzzy text matching with quantity-awareness, a semantic embedding stage via the OpenAI API for harder cases, and a hand-curated staples bridge for the most important items. The confidence of each match is tracked, so auto-matched, semantically matched, and manually curated prices are all distinguished.

Once matched, prices flow into an append-only observations table that gives historical trends for free. The frontend, a Next.js app connected to Supabase Postgres, reads this data at request time and renders it on the dashboard.

For Trader Joe’s historical pricing before the scraper launched, I filtered a publicly available third-party price dump through the curated staples allowlist and loaded it into a separate proxy history table, keeping it isolated from live scrape data.

The whole infrastructure costs $0 per month. Vercel hosts the frontend, Supabase handles the database on its free tier, and GitHub Actions runs the scrapers.

What I Owned—and What Codex Accelerated

I owned the product scope, architecture, data model, matching strategy, and validation decisions. Codex accelerated the implementation across migrations, scrapers, pipeline code, and the web interface. The useful distinction was not who typed each line; it was which decisions required context, tradeoffs, and verification—and those stayed with me.

The most impressive part was how it kept up with schema changes across iterations. As the data model evolved, it updated migrations, scripts, and pipeline logic in sync without losing track of what had changed.

What Is Still Being Built

The matching pipeline is solid for Trader Joe’s and Whole Foods. Safeway is scraped but the matching pass hasn’t run at full scale yet. The next phases are a staples-focused weekly scrape cadence, QA dashboards to monitor scrape quality, and eventually crowdsourced price contributions with receipt upload.

Built April 2026 as part of the OpenAI Codex challenge. Stack: Next.js, Supabase, GitHub Actions, Vercel, OpenAI API.
